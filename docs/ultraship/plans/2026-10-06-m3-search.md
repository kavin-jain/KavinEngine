# M3 Search Additions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use ultraship:subagent-driven-development (recommended) or ultraship:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add standard search features to the NNUE engine one at a time, and keep each one only if SPRT accepts H1. M3 is done when ≥ 5 features are accepted, an LTC bundle check passes, and a mini-gauntlet estimate reaches ≥ 2600 (spec §8).

**Architecture:**
- Shared groundwork lands first as bench-identical commits:
  - the static-eval stack;
  - the `quiet` flag computed before `make`;
  - `see_ge` with its tests.

  A rejected feature therefore never removes something a later task needs.
- Each feature is then a few lines in `src/search.cpp`, run through one fixed loop: build base/dev → tests → bench → SPRT → commit (H1) or save the patch and revert (H0).

**Tech Stack:** C++17, fastchess SPRT (pentanomial, `normalized`), UHO_Lichess_4852_v1 book, `make`, Ordo.

**Depends on:** M2 committed (NNUE is the evaluation). Task 0 checks this mechanically.

## Machines (spec §3: "long runs go to lynxS")
| Machine | Role | Concurrency |
|---|---|---|
| lynxS (i3-7020U, 2 cores / 4 threads, AVX2, always on) | All feature SPRTs, 24/7 | 2 (one per physical core; Paperclip/Hermes keep the other threads) |
| MacBook Air M3 | Builds, training, and the LTC bundle check, overnight on AC only | 4 |

**STC on lynxS** = 8+0.08 × R, where R = (Mac bench nps) / (lynxS bench nps). Measure both single-threaded on the same commit and round R to 1 decimal. This keeps the node budget per move equal to the spec's STC on the Mac. R and the resulting TC go in `docs/testing.md` (Task 0). Re-measure R if the engine's nps changes by more than 20 %.

## Spec amendment (decided by Claude under Kavin's delegation; flagged in the report)
Spec §7.3 asks for LTC 40+0.4 on every search-shape change. At our throughput (≈ 100–300 LTC-equivalent games/hour across both machines), a per-feature LTC SPRT costs 1–3 days each. Instead:
- every feature must pass STC SPRT [0, 5];
- the final M3 bundle (all accepted features) must pass one **LTC SPRT [0, 10]** against the M2 base (Task 12). A bundle that fails LTC is bisected: drop the newest pruning feature and re-run.

This is added to spec §10 (decision log) in Task 0.

## Risk register
| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| SPRTs on the slow lynxS take days | High | Medium | Cap at 4,000 rounds (8,000 games) via `ROUNDS`. Unresolved = not merged, logged "inconclusive". Reserve features (Task 11) cover shortfalls |
| lynxS load spikes (Paperclip spawns Claude Code) cause time losses | Medium | Medium | Concurrency 2, `nice`-free (engines must keep full priority). Time losses are counted in the log; > 1 % time losses invalidates the run |
| lynxS link drops (USB Wi-Fi) | Medium | Low | Matches run under `tmux` on lynxS, not over a live SSH pipe. fastchess `-recover` |
| A pruning feature hides a bug (fake mates/stalemates) | Low | High | `make test` (mate-in-1/2, stalemate, draw tests) before every SPRT. `best > -MATE_BOUND` guard on every move-loop prune |
| Features that pass STC lose at LTC | Medium | Medium | Task 12 bundle LTC check + bisect |
| ESP32 RAM | Low | Medium | Only `int eval_stack[MAX_PLY + 1]` is added (196 B at MAX_PLY 48). Continuation history (≈ 295 KB) is deferred to Plan 4 |

## Out of scope (Plan 4, after device measurements)
Continuation history (needs PSRAM on device), singular extensions, time-management refinements, Lazy SMP / dual-core.

## The SPRT loop (Tasks 2–11)
`<id>` = the task's short name. Every command runs from the repo root on lynxS unless noted. The repo is synced from the Mac with `rsync -az Makefile src pc tests tools nets s:Projects/Chess-Engine/`.

- [ ] **L1. Base.** `git status --short src tests` must be empty on the Mac. Then build the base on lynxS: `make EXE=build/base && build/base bench | tail -1 | cut -d' ' -f1`. The node count must equal the `Bench:` line of `git log -1 --grep='^Bench:'`.
- [ ] **L2. Tests (Mac).** `make test` → `all tests passed`.
- [ ] **L3. Dev + bench.** On lynxS: `make EXE=build/dev && build/dev bench | tail -1 | cut -d' ' -f1` → `<n>`.
  - `<n>` must differ from base. A functional change with an identical node count never ran.
  - The Mac must print the same `<n>` (cross-platform determinism).
- [ ] **L4. SPRT (lynxS, in tmux).** `tmux new -d -s sprt "CONCURRENCY=2 ROUNDS=4000 tools/sprt.sh build/dev build/base 0 5 <STC> 2>&1 | tee results/sprt/<id>.log"`. Poll `tail -5 results/sprt/<id>.log` every ~30 min until it shows `H0`/`H1` or ends at the round cap (= inconclusive).
- [ ] **L5a. H1:**
  1. Copy the log and PGN back to the Mac.
  2. Compress the PGN: `xz -9 results/sprt/<id>.pgn`.
  3. Commit: `git add -A src tests results/sprt/<id>.log results/sprt/<id>.pgn.xz && git commit -m "<feature>" -m "Bench: <n>" -m "SPRT [0, 5] STC <tc> (lynxS): <games> games, <W-D-L>, Elo <x ± y>, LLR <llr>"`.
  4. On lynxS: `cp build/dev build/base`.
- [ ] **L5b. H0 / inconclusive:**
  1. Save the attempt: `git diff src tests > results/sprt/<id>.patch`.
  2. Revert: `git checkout -- src tests`.
  3. Commit the patch, log and `.pgn.xz` with message `"SPRT rejected: <feature>"`.
- [ ] **L6. Log.** Append a row to `docs/sprt-log.md`; it goes in the same commit as L5a/L5b.

- [ ] **Step 4: Implement SEE.** In `src/movegen.h`:
```cpp
// Static exchange evaluation (swap algorithm, chessprogramming.org "SEE - The Swap Algorithm"):
// is the material balance of the capture sequence on to_sq(m) at least `threshold`?
// Castling, en passant and promotions count as 0. Pins are ignored.
bool see_ge(const Board& b, Move m, int threshold);
```
In `src/movegen.cpp`:
```cpp
namespace { const int SEE_VALUE[6] = {100, 300, 300, 500, 900, 0}; }

bool see_ge(const Board& b, Move m, int threshold) {
    const int fl = flags_of(m);
    if (fl != QUIET && fl != DOUBLE_PUSH && fl != CAPTURE) return 0 >= threshold;
    const int from = from_sq(m), to = to_sq(m);
    int swap = (fl == CAPTURE ? SEE_VALUE[type_of(b.mailbox[to])] : 0) - threshold;
    if (swap < 0) return false;  // even keeping the victim free is not enough
    swap = SEE_VALUE[type_of(b.mailbox[from])] - swap;
    if (swap <= 0) return true;  // even losing the mover keeps us at the threshold
    Bitboard occ = b.occ ^ bb(from) ^ bb(to);
    const Bitboard bishops = b.pieces[make_piece(WHITE, BISHOP)] | b.pieces[make_piece(BLACK, BISHOP)]
                           | b.pieces[make_piece(WHITE, QUEEN)] | b.pieces[make_piece(BLACK, QUEEN)];
    const Bitboard rooks = b.pieces[make_piece(WHITE, ROOK)] | b.pieces[make_piece(BLACK, ROOK)]
                         | b.pieces[make_piece(WHITE, QUEEN)] | b.pieces[make_piece(BLACK, QUEEN)];
    Bitboard attackers = (PawnAttacks[BLACK][to] & b.pieces[make_piece(WHITE, PAWN)])
                       | (PawnAttacks[WHITE][to] & b.pieces[make_piece(BLACK, PAWN)])
                       | (KnightAttacks[to] & (b.pieces[make_piece(WHITE, KNIGHT)] | b.pieces[make_piece(BLACK, KNIGHT)]))
                       | (KingAttacks[to] & (b.pieces[make_piece(WHITE, KING)] | b.pieces[make_piece(BLACK, KING)]))
                       | (bishop_attacks(to, occ) & bishops) | (rook_attacks(to, occ) & rooks);
    Color stm = b.stm;
    int res = 1;  // 1 = the side that made move m is winning the exchange so far
    for (;;) {
        stm = ~stm;
        attackers &= occ;
        const Bitboard mine = attackers & b.colors[stm];
        if (!mine) break;
        res ^= 1;
        int pt = PAWN;
        while (!(mine & b.pieces[make_piece(stm, PieceType(pt))])) ++pt;
        if (pt == KING) return (attackers & b.colors[~stm]) ? res ^ 1 : res;  // king may only take an undefended piece
        if ((swap = SEE_VALUE[pt] - swap) < res) break;
        occ ^= bb(lsb(mine & b.pieces[make_piece(stm, PieceType(pt))]));
        if (pt == PAWN || pt == BISHOP || pt == QUEEN) attackers |= bishop_attacks(to, occ) & bishops;
        if (pt == ROOK || pt == QUEEN) attackers |= rook_attacks(to, occ) & rooks;
    }
    return res;
}
```

### Task 3: Aspiration windows (`asp`)
- [ ] **Step 1:** In `search()`, replace the iterative-deepening loop with:
```cpp
    int prev_score = 0;
    for (int d = 1; d <= limits.depth && d < MAX_PLY - 1; ++d) {
        S.seldepth = 0;
        int delta = 25, alpha = -INF, beta = INF;
        if (d >= 4) { alpha = std::max(prev_score - delta, -INF); beta = std::min(prev_score + delta, INF); }
        int score;
        for (;;) {  // re-search with a wider window until the score lands inside it
            score = negamax(alpha, beta, d, 0, true);
            if (S.stopped) break;
            if (score <= alpha) { beta = (alpha + beta) / 2; alpha = std::max(score - delta, -INF); }
            else if (score >= beta) beta = std::min(score + delta, INF);
            else break;
            delta *= 2;
        }
        const bool complete = !S.stopped;
        if (S.pv_len[0] > 0 && (complete || d == 1)) { res.best = S.pv[0][0]; res.score = score; res.depth = d; }
        if (!complete) break;
        prev_score = score;
        if (verbose) print_info(d, score);
        if (S.budget.soft >= 0 && now_ms() - S.start >= S.budget.soft) break;
        if (limits.nodes && S.nodes >= limits.nodes) break;
    }
```
The window is never empty. After a fail-low, the new alpha is below the old alpha, which is below the new beta. After a fail-high, the new beta is above the score, which is at or above the old beta, which is above alpha. A search stopped mid re-search falls back to the last complete iteration: `pv_len[0]` is reset on entry, and `complete` is false.
- [ ] **Step 2:** SPRT loop, `<id>` = `asp`.
